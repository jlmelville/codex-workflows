# Workflow Retrospective Notes

When work spans phases or context windows, preserve a feature-orthogonal observation in the active
plan only when later work needs it to interpret validation, avoid a repeated failure, or make a
pending decision.

Useful plan-continuity observations include:

- repeated workflow, validation, benchmark, or handoff patterns;
- tool failures, sandbox limitations, or environment-specific workarounds;
- repo conventions that were not obvious from existing guidance;
- planning friction, missing context, or handoff gaps;
- a possible reusable lesson that a later phase must reassess;
- why the lesson is reusable beyond the current feature.

Keep these notes concise and evidence-based so a later retrospective can use evidence from every
phase, not only the current context window.

When standing or task instructions authorize capture, preserve qualifying observations through
`$skill-retro` while the evidence is fresh. `$papercut-capture` forwards to the same stream.
Do not copy operational observation records into a tracked plan; retain only the execution
consequence or decision that later work needs. Review owns remedy and reuse judgments.
