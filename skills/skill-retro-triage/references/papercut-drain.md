# Bounded Papercut Review And Drain

Use during live triage or a broader learning-process review. List open
observations with the reconciled helper's `papercuts` command. In triage,
select a small relevant cluster using the active destinations, a repeated
obstacle, or an actionable local fix. State the selection and what remains;
unrelated backlog does not block the main batch. Broader process review owns
coverage of the whole open inbox and recurring undrained clusters.

Classify each reviewed observation:

- `no-action`: no remedy is warranted;
- `local-fix`: the remedy belongs only to the originating repository;
- `candidate`: a reusable missing kernel is ready for retrospective admission;
- `external-owner`: another owner must act;
- `duplicate`: an existing papercut owns the same evidence and drain.

Name the concrete missing delta and smallest owner. Check existing coverage;
keep local wrappers out of reusable candidates. An `external-owner` outcome
does not authorize a message, and a `local-fix` outcome does not authorize edits
in another repository.

For read-only review, propose the outcomes and leave records unchanged. Source
implementation or ordinary candidate-processing authority alone does not
authorize papercut closure. When the user authorizes the selected papercut
drain, read the protocol's
[Installed Helper](../../skill-retro/references/state-protocol.md#installed-helper)
and [Papercut Intake And Closure](../../skill-retro/references/state-protocol.md#papercut-intake-and-closure)
sections. Create and validate candidate targets, or identify the surviving
duplicate, before closing with typed outcomes. Judge routed candidates in the
same run when that processing is authorized; closure alone does not accept a
candidate. Finish with helper `validate` and report closed and remaining items.

Evaluate the pilot in the next due process review: did bounded triage review
produce justified drains sooner, and what effort or duplicate review did it
add? Use available prior evidence, leave absent comparisons unknown, and
recommend keeping, adjusting, or retiring the route. Do not add a schedule or
make backlog size a closure quota.
