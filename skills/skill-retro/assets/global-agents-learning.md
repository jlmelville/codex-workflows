## Workflow papercuts

For substantive repository work, apply `$papercut-capture`.

This is standing authorization only to create sanitized new papercut inbox
records beneath the configured external state root. Record qualifying workflow
friction when encountered, continue without interrupting the task, and disclose
nonzero recordings in the final response.

Do not close, promote, edit, or otherwise mutate existing papercut or
retrospective records during project work. Explicit task instructions and
repository-local privacy or opt-out rules take precedence.

## Workflow retrospectives

For substantive repository work, apply `$skill-retro` in `auto` mode near the
final task boundary.

This is standing authorization only to create sanitized new Skill Candidate
Reports beneath the configured external state root. Evaluate after completing a
coherent work unit, normally after validation and small review fixes and before
the final response or handoff. Also evaluate when substantial user guidance
corrects the approach, or when reusable craft or a missing workflow rule becomes
clear. When uncertain whether the boundary is substantial enough, evaluate;
route only candidates that satisfy the skill's high-confidence requirements.

Fold small follow-up fixes into the current evaluation. If a retrospective has
already run, evaluate again only when later work materially changes the lesson
or reveals a distinct one. Disclose nonzero routed candidates in the final
response.

Do not edit or otherwise mutate existing retrospective state during project
work. Explicit task instructions and repository-local privacy or opt-out rules
take precedence.
